# Proposal: Horizon-Matched Full-State EMA over the Clean SAM Tail

## Summary

Add a deployable exponential moving-average model to EXP-004 without changing the online training path. Initialize the shadow state exactly when CutMix ends and periodic SAM begins at 75% charged progress. Thereafter, update the complete floating state from every completed online iterate with a charged-time horizon, copy integer buffers exactly, and use the EMA model for the experiment's single epoch-end evaluation. Preserve independent-image batches, full CutMix dose, period-two SAM, one optimizer update, and the 300-second budget.

EMA is preferable to SWA for this parent. SWA's strongest mechanism relies on a constant or cyclic late LR that keeps trajectory points diverse, whereas EXP-004 uses a strongly decaying cosine tail (`knowledge/papers/stochastic-weight-averaging.md`). Adding a SWA LR tail would bundle averaging with a schedule change. A time-scaled EMA can smooth the existing trajectory without altering optimization, data, or stochastic semantics (`knowledge/papers/how-to-scale-your-ema.md`).

## Exact Fixed Recipe

Use these preregistered constants:

```text
EMA_START = 0.75
EMA_TIME_CONSTANT_S = 0.05 * TIME_BUDGET_S = 15.0 seconds
EMA_UPDATE_PERIOD = 1 completed optimizer step
EMA_EVAL = true after initialization
```

The 15-second e-folding constant is horizon-matched to the fixed run rather than imported as a familiar decay scalar. The clean tail lasts 75 charged seconds, so it spans exactly five EMA time constants. Consequently, the transition snapshot's ideal residual weight at the end is `exp(-75/15)=exp(-5)=0.00674`: enough history to average several late checkpoints, but little enough initial-tail drag to follow final low-LR improvement.

At the beginning of the first batch whose known `progress >= 0.75`, copy the entire online model state into the preallocated shadow. This copy is inside the batch's charged timer. For every later batch, before its forward pass, the online model represents the prior completed optimizer step and `total_training_time` contains the exact charged duration through that step. Let

```text
delta_t = total_training_time - ema_last_training_time
beta = exp(-delta_t / EMA_TIME_CONSTANT_S)
```

and update every floating state tensor as

```text
ema_state = beta * ema_state + (1 - beta) * online_state
```

Copy every non-floating state tensor exactly from online to EMA. Then set `ema_last_training_time=total_training_time`. Updating at the next batch start guarantees that only restored, post-optimizer online iterates enter EMA; the final EMA may lag by one optimizer step, roughly 0.01 seconds and less than 0.1% of the 15-second horizon. Record this lag instead of performing an uncharged post-budget update.

Do not bias-correct. Initialization from the actual online state at the transition makes the weights sum to one from the first EMA update. Do not warm up or ramp beta, tune the horizon, or choose between EMA and online accuracy after observing test metrics.

## Full-State and BatchNorm Semantics

Create the shadow with `copy.deepcopy(model)` after model construction. Deep copy consumes no model-initialization RNG, unlike constructing a second WRN, and preserves channels-last parameter layout. Set all shadow parameters `requires_grad_(False)` and keep the shadow out of the optimizer.

Build and statically reconcile name-aligned references for:

- all trainable parameters: floating, exponentially averaged;
- BatchNorm `running_mean` and `running_var`: floating, exponentially averaged with the same beta;
- BatchNorm `num_batches_tracked`: integer, copied exactly on every update;
- any other registered floating/non-floating buffers: averaged/copied by the same dtype rule.

This is deliberately full-state EMA. Do not copy online BatchNorm statistics only at evaluation: that would pair averaged weights with a different online state. Do not run a BatchNorm recalibration pass, which would add training-data work outside the charged budget. Averaging running statistics is an approximation because they were generated by changing online weights, but it produces one self-contained shadow state and avoids a second data pass.

The online BatchNorm path remains exactly EXP-004: primary passes update buffers once; the SAM perturbed pass disables tracking. EMA runs no training forward and updates its buffers only from the restored online state. At evaluation, the frozen `Eval.evaluate` sets the chosen model to eval mode and uses the shadow's own full state.

## Integration with Training and SAM

Modify only `train.py` from EXP-004.

1. Import `copy`, instantiate the shadow and aligned state references during setup, and verify identical keys, shapes, dtypes, devices, and memory formats.
2. Move `t0=time.time()` before transition initialization/EMA update so every copy and lerp is charged. Run the EMA maintenance before the current batch's online forward.
3. Leave model, DataLoader, transforms, CutMix generators/helper/gate, LR, drop path, SGD, and every SAM operation unchanged.
4. EMA never sees temporarily perturbed SAM weights. A scheduled pulse still snapshots, perturbs, replays CUDA RNG, suppresses second-pass BatchNorm tracking, restores parameters, and performs one Nesterov update. That resulting online iterate is incorporated at the next batch start.
5. Preserve one evaluation per epoch. Before EMA initialization, call `evaluator.evaluate(model, device)`. Once initialized, call `evaluator.evaluate(ema_model, device)` instead. Never evaluate both in one epoch. The best accumulator may contain early online and late EMA checkpoints under this fixed switch; final accuracy and loss must be from EMA.
6. Calling `evaluator.evaluate(ema_model, ...)` must not change online training mode. `model.train()` remains at each epoch start; the shadow remains detached and evaluation-only.
7. Keep all required final summary keys unchanged and add a separate EMA audit line.

This evaluation policy is fixed by training progress, not accuracy. It does sacrifice visibility into late online checkpoints, but evaluating both would violate the cadence constraint and create a model-selection advantage over the parent. The EMA initialized at the exact online transition state avoids a cold or randomly lagged evaluator.

## Compute and Memory Cost

The WRN has 2,748,890 parameters, about 10.5 MiB in FP32, and very small BatchNorm buffers. A shadow model adds approximately 11 MiB persistent state. Updating all floating state each late step reads online plus shadow state and writes shadow state, roughly 30-35 MiB of memory traffic per step for the final quarter. On H20 this is bandwidth-small relative to the WRN forward/backward, although Python/kernel-launch overhead must be controlled.

Use `torch._foreach_mul_`/`torch._foreach_add_` or `_foreach_lerp_` for compatible floating tensors, with a clear fallback for buffers, to avoid one kernel per parameter. The update adds no model forward, backward, activation, random draw, or optimizer state. Expected charged overhead is below 2%, peak allocation should remain below roughly 1.22 GiB versus EXP-004's 1,190.5 MiB, and optimizer exposure should remain above a preregistered 25,000-step floor. A warm GPU latency smoke must verify that floor without using accuracy.

Evaluation cost is excluded by the frozen protocol and remains one model forward over the test loader per epoch; evaluating EMA instead of online does not add evaluation work.

## Evidence and Interaction with History

Weight averaging improves CIFAR residual-network generalization by moving from a boundary trajectory point toward a wider central solution with little training overhead (`knowledge/papers/stochastic-weight-averaging.md`). EMA scaling work shows that momentum cannot be chosen independently of update cadence and training scale; specifying a time constant and deriving beta from actual charged exposure preserves the intended horizon as throughput changes (`knowledge/papers/how-to-scale-your-ema.md`).

The system understanding explicitly identifies late-iterate variation and unused memory as open headroom. EXP-006's final four accuracies spanned 0.15 points, and EXP-007's last eight had about 0.062 standard deviation, while both preserved step throughput. A full-state shadow directly targets iterate variation without replacing CutMix, changing image identity exposure as EXP-005 did, or altering SAM geometry as EXP-007 did.

The direct parent signal is weaker: EXP-004's final accuracy equaled its 95.40% best, so it did not show an obvious best-to-final gap. The child oscillations occurred under changed mechanisms and cannot prove EMA will improve the parent. EMA is therefore principled and low-risk, but its evidence for a large top-1 gain on this exact trajectory is limited.

## Attribution

This is an additive evaluator-model/training-state mechanism. Online EXP-004 optimization remains unchanged apart from charged EMA maintenance. A gain is attributable to the complete fixed package: late full-state EMA with a 15-second time constant and EMA-only tail evaluation. It cannot isolate parameter averaging from floating BatchNorm-buffer averaging or the fixed evaluator switch.

Wall-clock overhead can slightly change total optimizer steps, CutMix count, and SAM pulse count. Audit exact exposure and do not attribute sub-threshold differences solely to EMA if the charged horizon changes materially. The minimum 25,000-step floor bounds this confound.

## Expected Effect and Falsification

The formal parent-relative gate is `best_test_acc >= 95.50%`. A realistic central expectation is **+0.05 to +0.20 points**, with a plausible but low-confidence ceiling near +0.30. This mechanism is **not likely to clear +0.30 points** on EXP-004: the parent already finished at its best checkpoint, the cosine/SAM tail may be too converged for trajectory averaging to move far, and no matched local EMA result exists. It should be deprioritized if candidate selection requires a likely effect of at least 0.30 rather than low-cost variance reduction.

The hypothesis is that the fixed EMA will reach at least 95.50% while preserving at least 25,000 steps and reducing late checkpoint variation. It is falsified as an accuracy intervention if `best_test_acc < 95.50%`, even if final loss or calibration improves. It is also falsified mechanistically if online-to-EMA parameter distance is effectively zero, the transition weight does not decay near `exp(-5)`, or state/update audits fail. Do not shorten the horizon or switch back to late online evaluation after seeing results.

An improved final loss without the accuracy gate should be interpreted like EXP-005: probabilistic smoothing without enough corrected class decisions. A lower tail spread is supportive but cannot be measured against online within the same run without extra evaluations, so only the EMA evaluation trajectory may be reported.

## Audit Contract

Startup output must report `ema_start=0.75`, `ema_tau_s=15.0`, `ema_update_period=1`, `ema_eval=tail_only`, shadow parameter/buffer counts, floating/non-floating element counts, and inventory parity.

Final audit output must include:

- initialization step, progress, and charged time;
- update count; min/mean/max `delta_t` and beta;
- accumulated elapsed EMA time and exact product of betas (transition-state residual weight);
- last-update lag in steps and charged seconds;
- online-to-EMA FP32 parameter L2 distance and relative distance at final state;
- floating parameter updates, floating buffer updates, and integer buffer copies;
- online evaluation count, EMA evaluation count, first EMA evaluation epoch;
- unchanged CutMix and SAM counts/ratios;
- inventory, nonfinite, state-key, dtype/device, and update-order failure counts.

Expected end-state checks are product-beta close to `exp(-elapsed/15)`, approximately 0.0067 if the full 75-second tail is captured; last lag at most one step; all failure counts zero; CutMix ratio near 0.5; SAM ratio exactly period-two; and EMA updates equal completed post-initialization iterates minus at most one.

## Smokes and Verification

Before launch:

1. **Closed-form decay**: feed fixed scalar states and irregular `delta_t` values; verify recursive EMA, `beta=exp(-delta_t/15)`, and product-beta identity against FP64 manual calculations.
2. **Full-state inventory**: reconcile every named parameter and buffer; verify floating tensors lerp, integer counters copy, shadow tensors require no gradients, and optimizer owns no shadow state.
3. **Deep-copy RNG**: snapshot global CPU/CUDA and CutMix generator states around shadow creation and prove they do not advance.
4. **BatchNorm semantics**: simulate primary and SAM passes, verify online buffers update once, shadow floating buffers update only through EMA, integer trackers copy, and no BN recalibration/data pass occurs.
5. **SAM ordering**: prove an EMA update observes restored post-optimizer base parameters from the prior step, never a perturbed snapshot or first-pass gradient state.
6. **Evaluation cadence**: simulate epochs spanning progress 0.75; verify exactly one evaluator call per epoch, online before initialization, EMA after, and final metrics from EMA.
7. **Parent parity**: with EMA maintenance disabled before 75%, verify early CutMix outputs, RNG, loss, parameters, and counters match EXP-004. Verify online updates remain parent-identical after 75% aside from wall-clock step count.
8. **GPU latency/memory**: benchmark warm fused full-state updates inside the charged interval, project at least 25,000 total steps, and verify peak memory comfortably below H20 capacity.
9. **Failure cases**: mismatched key/shape/dtype/device, nonfinite shadow state, update during perturbation, and uncharged final catch-up must fail rather than silently continue.
10. **Static checks**: compile/lint `train.py`, confirm only it differs from EXP-004, and validate complete config/audit fields.

Run exactly once after confirming physical GPU 0 is the approximately 98 GB NVIDIA H20:

```bash
timeout 600s env CUDA_VISIBLE_DEVICES=0 uv run train.py > run.log 2>&1
```

Verify exit 0, no nonfinite/CUDA errors, 300-second charged budget, total runtime below 600 seconds, one evaluation per epoch, `num_params=2,748,890`, `num_steps>=25,000`, exact CutMix/SAM preservation, valid full-state EMA horizon/audits, complete summary, and `best_test_acc>=95.50%`. Remove `run.log` after analysis. No repeat, horizon search, online/EMA metric selection, or seed reroll is permitted.

## Effort

**Medium.** The arithmetic is small, but state inventory, dynamic horizon scaling, BatchNorm coherence, update ordering around SAM, and single-model evaluation semantics require careful implementation and focused integration tests.
