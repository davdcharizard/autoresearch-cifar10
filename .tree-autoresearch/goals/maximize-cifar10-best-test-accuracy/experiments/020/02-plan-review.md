# EXP-020 Plan Critique — prioritized concerns

**1. [Milestone 3 / Verification step 4 / Abort Criteria] The one-shot "decisive" preflight couples noise-sensitive timing thresholds to an irrevocable leaf abort.** The gate stack — ratio MAD/median ≤1.5% across only five rounds, every round ≤1.06, parent drift ≤4%, live-allocation growth ≤1 MiB — is measured on a shared H20 where transient clock/contention jitter of 2–5% is routine, and the plan forbids any rerun after "a complete numeric failure." A single contention blip during one 215-step round can permanently kill an otherwise sound experiment for reasons unrelated to the hypothesis. Worse, the single-repair clause covers only a harness that *throws before emitting a vector*: a harness that emits a complete vector computed with a buggy formula (wrong weighting, mis-paired arms) is unfixable by the plan's own rule, converting a harness bug into a final leaf verdict. The no-retry discipline is appropriate for the accuracy run (anti-seed-hacking); applying it to a pure infrastructure/latency measurement conflates the two.

**2. [Milestone 2 / Verification step 5 / Abort Criteria] Brittle numeric tolerances on report-only diagnostics can invalidate the sole metric run.** The plan lets integrity assertions fail the run for "preregistered … numerical violations," and preregisters `1e-5` *relative* error on the raw/L2/cross removed-energy reconstruction and a residual `≤1e-6` with no stated normalization (absolute vs relative, per-row vs aggregate). The cross term `2·⟨raw_mean, l2_mean⟩` can be negative and nearly cancel the raw term, making the relative-error denominator arbitrarily small late in training when gradients shrink — catastrophic cancellation in FP32 inputs is not bounded by FP64 accumulation. A diagnostic that "never changes the applied update" (Milestone 2's own words) could thus destroy a valid 300-second metric result. The tolerances need an absolute-or-relative hybrid form and an explicit residual normalization, or reconstruction failure should demote to a reported anomaly rather than a run-failing assertion.

**3. [Verification steps 3–4 / Code Changes] Module importability of `train.py` is assumed, and the "parent arm" may not be the parent's actual code.** The smoke and preflight import "the exact production helpers through the guarded module" and "replace the import-constructed evaluator before any iteration" — which presupposes `train.py` has (or will be given) a `__main__` guard and import-safe structure. If EXP002's `train.py` executes its training loop at module scope, the preflight's parent arm requires a *modified* copy of the parent to be loadable at all, so "identical forward/raw-backward state" is proven against an edited parent, not commit `a36dc09`'s code. Any restructuring for importability is also an un-audited change to startup behavior in the candidate that the "single-variable ablation" claim does not account for. The plan should state how the parent arm is materialized and prove the guard restructure is a no-op on the executed path.

**4. [Milestone 3 / Verification step 4] The forced 80/80/55 path composition contradicts "production-faithful … aligned RNG" for a probabilistic CutMix parent.** EXP002 applies CutMix by per-step stochastic draw, so a preflight round with an exact deterministic path mix must override or resample the draw, changing RNG consumption relative to production while the plan simultaneously requires aligned RNG and identical raw-backward state between arms. Additionally, the hard-coded weights `0.375/0.375/0.25` encode an *assumed* production phase mix; if EXP002's realized CutMix fraction differs, both the weighted ratio and the `floor(27950/R)` dose projection are biased, and the audit-cadence-512 steps (whose extra row-mean/FP64 work is charged in the real run) are never exercised in a 215-step round, so their cost is excluded from `R`. The plan should reconcile the forced composition with the RNG-parity claim and state where the phase weights come from.

**5. [Milestone 4 / Configuration Changes] Preregistered closure of the raw-order and phase-limited variants exceeds what this run's evidence can support.** A single-seed `≤95.23%` result on the *official-order* rule is declared to close both untested variants, on the strength of report-only magnitude audits (phase buckets, raw-vs-L2 row-mean decomposition). Those audits measure how *large* the L2 common-mode and per-phase removed energies are, not whether removing them *hurts* — magnitude cannot arbitrate the causal question the raw-order and phase-limited hypotheses pose. The plan even concedes single-seed noise by carving out a 95.24–95.32 "unresolved" band, yet a 95.22 vs 95.24 outcome (one noise-width apart) flips between "close three hypotheses" and "unresolved." The closure clause should be scoped to what the run tests, or explicitly conditioned on the audit values meeting stated magnitude criteria.

**6. [Milestone 2 / Milestone 1] The raw-row-mean capture reorders per-tensor work on audit steps in charged time without a stated equivalence check.** On cadence-512 steps the plan reads convolution row means *before* the single `torch._foreach_add_` L2 application, requiring either a pre-add pass over the 16 conv gradients or splitting the foreach call — a code path that differs from the non-audit step's path inside the charged region. The smoke tests prove foreach/loop equivalence and RNG neutrality generally, but no check asserts that an audit step's *applied update* is bitwise identical to a non-audit step's on the same state, which is the actual invariant Milestone 2's "never changes the applied official-order update" claim depends on.
