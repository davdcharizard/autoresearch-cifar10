1. **High | Summary/Code Changes** (`02-plan.md:5,33`; `train.py:151-160`): the “bit-equivalent to EXP-004 at init” claim is false. Adding `GatedResidual(512)` before `self.fc`, then calling `self.apply(self._weights_init)`, consumes extra Kaiming RNG draws before `fc` is initialized, so `fc.weight` changes versus EXP-004 even though the new block output is identity. The smoke only checks `blk(h)==h`, not whole-model equivalence, so attribution/early-trajectory assumptions are weaker than stated.

2. **High | Verification Protocol** (`02-plan.md:60,63`; `train.py:355,372-381`): several pass/fail checks are not executable numeric checks against the actual log format. `grep "^total_seconds:" run.log < 600` is ambiguous/invalid as written, and the per-epoch max command returns bare `96.00` while summary `best_test_acc` is `best_test_acc:    96.00%`. Without explicit normalization, the genuineness and wall checks can false fail or be checked manually/inconsistently.

3. **Medium | Abort Criteria vs Chosen-Idea Premise** (`01-brainstorm.md:77,91`; `02-plan.md:21,51`): the brainstorm says the throughput read is a mandatory gate on projected epochs ≥~110, but the plan makes `<110` “NOT an auto-abort.” That means the run can proceed after the selected idea’s throughput premise is already falsified, making a no-improvement result hard to distinguish from known under-annealing.

4. **Medium | Reward-Hack/Leakage Checks** (`02-plan.md:63`; `train.py:215-217,348`): the greps are too brittle if the manual diff-content check is not enforced perfectly. `datasets.CIFAR10(train=True)` does not literally match the current split multi-line call, the leakage grep misses aliases/positional `False`, `.targets`, or access through `evaluator.loader`, and `grep -c "evaluator.evaluate("` counts call sites rather than proving once-per-epoch execution.

5. **Medium | Dead-Block Smoke** (`02-plan.md:14,52`): `alpha.grad != 0` on `model.layer3[3]` is necessary but not sufficient for the claim that the new block trains. At `alpha=0`, branch conv/BN parameter gradients are zero on the first backward; the plan does not require a one-step update proving `alpha` is in the optimizer and that branch params receive nonzero gradients on a second backward.

6. **Low | Scope Sequencing** (`02-plan.md:27,62`; `01-definition.md:23-24`): the plan says to record results in `03-execute.md`, while the scope check expects `git diff --name-only ...` to list only `train.py`. If documentation is written before the scope check, the plan invalidates its own verification.

7. **Low | Wall-Time Guard** (`02-plan.md:40-44,60`; `train.py:31,198`): `total_seconds` starts inside `main()`, after top-level `evaluator = Eval()` construction. The real 600s guard is the `timeout` process exit code; the plan should explicitly preserve the background PID and `wait` status, otherwise `total_seconds < 600` can under-report actual process wall time.
