# Plan Critique - EXP-031

1. **[Milestone 2 / Verification Procedure 6] The timing gate can certify a 2% speedup while permitting 3% noise in every arm.** Taking a ratio of independently computed arm medians after only requiring each population CV to be `<=3%` does not establish that the candidate is materially faster: admissible run-to-run variation is larger than the `1.02` treatment threshold, and `A-C-C-A-A-C` ordering alone does not turn those six windows into an uncertainty bound. This can spend the sole score on timing noise and then misattribute extra exposure to channels-last. Predeclare paired/blockwise accepted-candidate ratios and require a conservative lower bound (or every balanced-pair ratio) to clear `1.02`; alternatively tighten variability below the claimed effect. Keep the reciprocal fixed-time formula, which is the correct formula for the 195/105-second phases.

2. **[Verification Procedure 4-5 / Evaluator Compatibility] The evaluator simulation covers batch 256 but omits the frozen evaluator's real final batch of 16.** `prepare.py` uses 10,000 test examples, `batch_size=256`, and `drop_last=False`, so every evaluation ends with a `[16,3,32,32]` input. The forward-entry conversion and channels-last `adaptive_avg_pool2d(...).view(...)` must be checked for both batch sizes; a 256-only synthetic check cannot prove the exact frozen contract and could allow a scored run to fail only at evaluation. Require finite, shape-correct, mutation-free contiguous-versus-preconverted checks at batch 256 and batch 16.

3. **[Milestone 1 / Verification Procedure 8] The proposed production memory-format audit is a constant claim, not a runtime audit.** Printing `Training memory format: channels_last` will satisfy the log parser even if model weights or the first post-mixup input are not actually channels-last, while Procedure 8 treats presence of that line as proof of scored-run layout. Make the startup/first-batch audit derive from `is_contiguous(memory_format=torch.channels_last)`, strides, and dtype for an actual convolution weight and the actual hard/mixed model input, then require those measured fields in `run.log`. Otherwise the score's “wrong layout audit” abort criterion is not testable from the scored artifact.

4. **[Verification Procedure 5] Identical accepted/candidate argmax on arbitrary synthetic logits is neither a necessary channels-last invariant nor a robust semantic gate.** A correctly implemented layout change can flip a near-tied synthetic prediction while satisfying the preregistered logit/CE error bounds, causing a false abort; conversely one concatenated gradient relative-L2 bound can hide a localized layer error. Fix and document the deterministic fixtures, treat argmax agreement as informational or exclude samples with a preregistered accepted-logit margin below the numerical tolerance, and enforce the gradient/update bound per named tensor or per layer. Include bounded cross-layout BatchNorm running-stat changes, because those buffers are part of the one-step training state but are absent from the current accepted/candidate update comparison.

5. **[Verification Procedure 5 / Candidate replay] “Restored state/RNG” is underspecified for a bitwise replay under `cudnn.benchmark=True`.** Restoring only model, optimizer, and RNG after one path has already selected/warmed cuDNN algorithms can compare different autotune/cache histories rather than deterministic candidate execution; stale `.grad` tensors and input/layout allocations are additional unlisted replay state. Warm the exact candidate shapes before taking the replay snapshot, synchronize, clear gradients, clone fixed logical inputs in the same layout, and define the snapshot as parameters, buffers, optimizer state, CPU/CUDA RNG, and mode. Replay twice from that post-warm snapshot without clearing or changing backend flags/caches between arms, so a bitwise failure diagnoses production nondeterminism rather than harness setup.
