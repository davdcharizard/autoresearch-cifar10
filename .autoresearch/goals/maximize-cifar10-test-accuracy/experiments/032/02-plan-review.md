# Plan Review EXP-032

1. **[Verification Procedure 5 / Milestone 2] The pixel-confinement claim is false if "pre-normalization" means the production output after RandAugment.** Geometric RandAugment operations can move or interpolate padding-derived values into locations whose crop-space source was originally inside the image; horizontal flip also requires flipping the padding mask. Test confinement immediately after `RandomCrop`, or after a forced flip with the mask flipped identically, with RandAugment bypassed. Test the active full transform separately only for decision/RNG alignment. Build the independent reflection oracle with `numpy.pad(..., mode="reflect")` and crop it directly rather than using torchvision's own `functional.pad`, or the check can reproduce the same implementation error it is meant to detect. Use an asymmetric fixture whose reflected source pixels are all nonzero before requiring a difference at every padding-touching offset.

2. **[Verification Procedures 4, 6, and 7] Target order and post-iterator main RNG do not prove that forkserver workers made the same crop, flip, and RandAugment decisions.** Those observations cover the main-process sampler only; crop, flip, and the private RandAugment stream live in each persistent worker, while candidate image hashes must differ. Add a preflight-only instrumented worker transform/dataset that returns sample index, worker id, crop `(i,j)`, flip bit, active flag, and RandAugment private-state/op/sign hashes. Run fresh accepted/candidate arms from independently restored seed-42 states, in production construction order, and require those traces to match per sample across the exhausted active epoch and the inactive next epoch. Tear each loader down before restoring state for the other arm. A separate shared-byte marker test is useful but cannot substitute for exercising the production transform sequence.

3. **[Verification Procedure 4] The crop/flip replay needs explicit RNG restore points or it can accidentally validate a shifted stream.** `RandomCrop.get_params` consumes two global CPU `torch.randint` draws and `RandomHorizontalFlip` then consumes one `torch.rand`; calling the manual replay and production transform successively from one state will not select the same decisions. Restore the identical saved state independently before the accepted production call, candidate production call, and manual `get_params`/flip replay, then compare all three terminal states. Also assert that PIL constant/NumPy-reflect padding itself consumes no torch RNG. For RandAugment, equal private terminal states only proves an equal draw count; independently replay or record the chosen op index and sign to prove equal decisions on the intentionally different images.

4. **[Verification Procedure 8 / Abort Criteria] The loader timing does not define a valid `projected >=130 passes` calculation.** In `train.py`, iterator wait happens before `t0`, so loader latency affects wall time but not the 300 counted GPU seconds; scaling 133.00736 passes by accepted/candidate loader-epoch time would therefore be wrong. Treat unchanged shapes/model/counted body as the exposure argument, or add matched complete counted-body timing on real accepted/candidate batches if an exposure projection is required. For wall feasibility, precommit the actual formulas using separately measured active and inactive epoch medians, a 65/35 weighted candidate/base differential anchored to EXP027's 345.3 seconds, and a live absolute projection anchored to its 300 counted plus 45.3 non-loader seconds. Print arm order, all epoch windows, weighted medians, CVs, and both projections before assertions.

5. **[Code Changes / Verification Procedures 3 and 7] "Fail-closed evaluator" is underspecified for executing two source modules.** `train.py` constructs `evaluator = Eval()` at import time, so `prepare.Eval` must be replaced before importing the candidate or executing the `git show` oracle. Require every construction to be the guard object, make its `evaluate` raise, and guard against any `datasets.CIFAR10(train=False)` construction; otherwise the preflight can touch the frozen test set before its later assertion. Keep accepted and candidate in separate module namespaces so the oracle does not reuse candidate classes or globals.

6. **[Milestones 3-4 / Abort Criteria] The `<130` realized-pass outcome has no precommitted family verdict.** The plan says such a valid score counts and cannot be rerun, but says only a normal-exposure miss closes the padding family and does not state whether a `<130` primary-metric success can enter the frontier. Specify both branches before execution: whether the primary metric still accepts under the task's actual hard constraints, how a low-exposure miss is classified, and exactly which of reflection/symmetric/replicate/alternate-width treatments are closed. This must not be decided after seeing accuracy.
