# EXP-017 Plan Review

1. **Milestone 3 / `train.py` diagnostics (lines 18, 26, 28) specify unbounded tensor caching inside the scored path.** At roughly 28,000 steps, retaining a detached `[256,128]` scale or logit tensor for both gates costs about 7.3 GB per cached quantity in FP32; retaining scales plus feature-logit components can exceed 14 GB. Keeping them on GPU risks OOM and changes peak memory, while copying them to CPU every forward introduces synchronization and can materially reduce the number of updates in the fixed 300-second budget. Replace full-tensor caching with fixed-size, on-device streaming sufficient statistics (counts, sums, squared sums, saturation counts, and norm sums), synchronize only after training, and ensure the throughput preflight measures the exact production instrumentation rather than an uninstrumented gate.

2. **Milestone 1 / model construction (lines 8, 9, 27) does not specify a CPU-only seeding operation, so the claimed CUDA-RNG preservation is not guaranteed by `torch.random.fork_rng(devices=[])`.** A natural implementation using `torch.manual_seed(ATTENTION_INIT_SEED)` also seeds CUDA, but a fork over `devices=[]` restores only the CPU generator. That shifts the post-construction CUDA RNG despite the plan's equality requirement and can alter the training trajectory. Pin the implementation to a CPU-generator-only seed operation or include and restore the actual CUDA device state, and make the semantic preflight compare serialized CPU and CUDA RNG states separately.

3. **Code Changes / model construction (line 27) leaves gate attachment relative to the existing `WideResNet(...).to(device)` call ambiguous.** The accepted source moves the model to CUDA immediately after construction; attaching newly created `Stage3SE` modules after that call leaves their parameters on CPU and fails on the first stage-3 forward. Require attachment inside `WideResNet.__init__` after the accepted `self.apply(...)` but before the outer `.to(device)`, or explicitly move each attached gate to the model device before optimizer grouping, and have preflight assert every gate parameter shares the accepted model's device and dtype.

4. **Milestone 3 / diagnostic definitions (lines 18, 28, 57) are not fully preregistered despite being used for mechanism interpretation.** “Across-example variance,” “saturation fraction,” and “feature-versus-bias logit norms” omit the aggregation window, variance axes/weighting, saturation cutoff, and norm definition; different reasonable post-run choices can support different attention-versus-static-scaling narratives. Define these formulas and their training-step population before scoring, including whether mixed and hard-label phases are pooled or reported separately, while keeping them observational.
