# EXP-016 Plan Review

1. **[Critical: Milestone 1 / Code Changes / seed-reroll constraint] The supposedly fixed local initialization seed is never specified.** The plan says only "a fixed local CPU RNG fork" and "one fixed initialization seed" (`02-plan.md:8,27`), while the chosen proposal explicitly requires the numeric seed to be preregistered before implementation. The appended block contains 295,424 trainable parameters, so choosing or changing this unspecified value is a materially different initialization and leaves an execution-level path to seed selection after preflight or a failed implementation, contrary to the goal's no-seed-reroll constraint. Put one exact numeric seed (or one deterministic, non-searchable derivation from the accepted post-construction RNG state) in the plan and require the production diff/preflight to attest that value before the scored run.

2. **[High: Milestone 1 / Verification Procedure 3] "Create one accepted `PreActBlock`" does not specify the required explicit initialization operation, and the proposed preflight cannot prove it.** In accepted `train.py`, constructing `PreActBlock` first applies `nn.Conv2d`'s default initialization; the accepted Kaiming-normal weights are installed only later by `WideResNet.apply(_weights_init)`. Appending a freshly constructed block after the base model's `self.apply` therefore silently leaves PyTorch defaults unless the implementation explicitly reapplies the accepted initializer. Requiring merely "Kaiming-scaled," nonzero weights and a successful update (`02-plan.md:8,54`) is not an exact check of distribution, mode, or deterministic tensors. Specify that both convolutions and BatchNorms receive the exact accepted `_weights_init` routine inside the fork, then compare every new-block tensor bitwise against an independently constructed expected block under the preregistered RNG procedure.

3. **[Medium: Milestone 1 / Configuration Changes] The constructor control flow is ambiguous between direct `[1,2,3]` construction and accepted-first mutation.** The plan simultaneously says to introduce explicit scored stage depths and to construct/initialize `[2,2,2]` first (`02-plan.md:7,27,32`), but does not state whether `WideResNet(STAGE_BLOCKS, ...)` initially passes `(1,2,3)` into `_make_layer` or always builds `(2,2,2)` before applying the exchange. The former shifts initialization of all later shared tensors and defeats the central control even though the final topology is correct. Define the exact production constructor sequence and require that the common-state comparison covers all named surviving parameters and buffers against an unmodified accepted reference initialized from the same saved state.
