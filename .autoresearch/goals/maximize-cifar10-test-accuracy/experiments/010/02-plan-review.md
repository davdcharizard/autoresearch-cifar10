1. **Highest - Verification Procedures 4-6 leave the production branch mix undefined in the threshold-setting preflight.** The plan says the timed step reproduces `progress/mixup`, but it never defines the synthetic `total_training_time` sequence or whether the 150 measured steps run the mixup branch, the hard-label branch, or both. Starting at zero would benchmark only mixup, whose input interpolation and second cross-entropy add width-independent work and can make `accepted_ms / candidate_ms` more favorable than the full run's 65% mixup / 35% hard-label workload. Preregister identical per-path progress values and either measure both branches separately with a fixed 65/35 weighted aggregate or use a fixed representative branch conservatively; derive window centers, retention, CV, and the 120-pass projection from that predefined aggregate only.

2. **High - Verification Procedure 8 can reject a valid fixed-budget run by requiring exactly `300.0` rounded training seconds.** The loop exits only after the step that crosses `TIME_BUDGET_S`, so the logged one-decimal value may legally be `300.1` (the task's own example shows this) even when timing is correct. Replace the exact rounded-value check with a bounded overshoot check tied to one final production step plus formatting tolerance, while still requiring that the run reached the 300-second budget and did not stop at `MAX_STEPS`.

3. **Medium - Code Changes / Verification Procedure 3 specify constructor validation but never test its contract, and the topology assertions cover only the widened tail.** A valid candidate smoke test cannot show that `WideResNet` rejects wrong-length, zero/negative, non-integer, or Boolean widths, and parameter count plus stage-3 shapes does not independently verify every stage, stride, and projection specified in the proposal. Add fail-closed negative constructor cases and assert the full accepted and candidate block topology: stage outputs, first-block input/output channels and strides, shortcut presence/shapes, second-block widths, final BN, and classifier. Keep these checks evaluator-free and require exact counts 691,674 and 961,562.

4. **Medium - Milestone 4 / the interpretation rule does not classify a scored negative that realizes fewer than 120 passes.** The preflight projection is explicitly non-authoritative, so a valid single run can pass the gate yet fall below 120 realized passes. Preregister that such a run is still a formal no-improvement and is not rerun, but is mechanistically inconclusive between inadequate optimization exposure and an unhelpful `[32,64,160]` allocation; only a stable negative at at least 120 realized passes rejects this allocation, and neither outcome rejects selective capacity generally.
