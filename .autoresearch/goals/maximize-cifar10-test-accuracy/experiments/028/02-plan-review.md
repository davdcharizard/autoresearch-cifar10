1. **[Milestone 4 / Verification Procedure 8] The decision rule still permits an evaluation-count gain to satisfy the primary metric.** The candidate is required to realize at least 145 passes versus EXP-027's 133.007, so unchanged every-fifth-epoch evaluation necessarily gives it more chances to set `best_test_acc`; requiring only `final_test_acc >=94.32%` still allows acceptance from a one-evaluation 94.42% spike whose endpoint merely ties the old model. This is the concrete reward-hacking path already identified in `01-idea-review.md`, and the weaker endpoint threshold does not close it.

2. **[Milestone 2 / Verification Procedure 3] The accepted-state oracle is underspecified and can collapse into a self-comparison.** The plan says `preflight.py` will prove accepted/candidate identity through the boundary, but it does not require loading `train.py` from commit `67c8e98`, storing an accepted state/trace artifact, or otherwise using an implementation-independent oracle. Two copies built from the modified candidate module, with freezing disabled in one, will match even if an accidental edit changed initialization, data policy, LR, optimizer construction, or pre-boundary computation in both copies; `git diff` inspection is not the claimed executable identity proof.

3. **[Milestone 2 / Abort Criteria / Verification Procedure 3] The proposed harness cannot prove the production boundary control-flow properties it lists.** `preflight.py` explicitly never constructs training data or invokes `main()`, while the freeze activation remains inline inside the real exhausted-`DataLoader` branch. A synthetic call to `freeze_training_prefix` plus source-string guards cannot establish that production invokes it exactly once, only after actual iterator exhaustion, at the same event as RandAugment disable, and never on a budget-exhausted partial epoch. Those are scored-run invariants, but the plan currently represents them as pre-timing runtime proofs and abort criteria without specifying an extractable/testable transition controller.

4. **[Verification Procedure 4] The 145-pass projection applies a hard-tail speed ratio to a whole-run exposure baseline as though accepted throughput were uniform.** EXP-027's 133.007 passes combine slower mixup/RandAugment steps and hard-label steps, while the intervention affects only the post-boundary hard tail; weighting total accepted passes by `0.656 + 0.344 * ratio` is therefore not the exact projection asserted. The measured mixup/hard timing difference is small, but the gate is placed exactly at 145.0, so the plan should not make a pass/fail decision on that approximation without separately using accepted early and accepted tail throughput (or a conservative error margin).
