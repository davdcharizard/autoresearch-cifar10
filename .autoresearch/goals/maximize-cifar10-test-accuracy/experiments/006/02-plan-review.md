# Adversarial Plan Review — EXP-006

1. **[Verification Protocol steps 3-4] The proposed separate-process model checks conflict with the requirement that the throughput preflight not load the test set.** `train.py` constructs `evaluator = Eval()` at module scope, and `Eval.__init__` immediately constructs the CIFAR-10 test dataset and loader. A normal `import train` to benchmark the actual `WideResNet` implementation therefore loads test data before the preflight begins. The plan does not specify an import-isolation mechanism that stubs `Eval` before loading `train.py`; duplicating the model in a benchmark would instead risk timing code that is not the experiment implementation. This must be resolved explicitly before execution so the unscored gate cannot silently touch test data or require an unplanned refactor outside the chosen dropout change.

2. **[Milestone 4 and Verification Protocol steps 6-7] The plan never enforces the hypothesis's realized-exposure floor on the scored run.** The brainstorm defines a valid mechanistic test as retaining at least 95% of EXP-002's 141.9 passes, but final verification only records `num_steps`; it does not require at least 26,329 steps (134.8 passes) or define how to interpret a run below that floor. The synthetic preflight is only a projection and cannot replace the observed count under the real loader, mixup, logging, and transition path. Without an explicit realized-exposure check, a negative result can be incorrectly attributed to dropout over-regularization when reduced optimization exposure is a live confounder.

3. **[Verification Protocol step 4] The matched throughput gate is under-specified for a hard abort decision near a 5% boundary.** “After warmup” and “the median” do not say that both p=0 and p=0.10 receive condition-specific warmup, use equal-duration/equal-iteration windows, alternate measurement order, or start from equivalent model/optimizer state. With only three windows and a small expected delta, cuDNN autotuning, cache/order effects, or differing optimizer state can move the ratio across 95%. The plan needs a deterministic matched harness definition and must retain the raw per-window timings; otherwise it can abort or admit the scored run based on a benchmark artifact.
